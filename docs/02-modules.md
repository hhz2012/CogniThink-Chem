# 化学伴思 功能模块拆分

> 版本：v0.2（D1 收口；M0–M2 已落地，M3 起未实现）
> 上游文档：[01-overall-plan.md](./01-overall-plan.md)｜下游文档：[03-tasks.md](./03-tasks.md)
> 本文档定义模块边界、职责、输入输出与依赖关系。D1 已定：模块以 C# / .NET 8 实现，接口签名按 C# 约定书写；D2–D5 为建议采纳、待确认，相关模块只依赖其"可回退部分"（解析器抽象、教材出处字段、来源/license 字段、视图模型）。

## 1. 模块总览

| 层 | 模块 | 一句话职责 |
| --- | --- | --- |
| 支撑 | **M0 工程骨架与规范** | 目录、编码规范、配置、CI 与文档约定 |
| 知识层 | **M1 知识本体与覆盖清单** | 知识点条目、层级（主干/延伸）、关联关系 |
| 知识层 | **M2 规则库与仲裁** | 规则存储、分层、优先级裁决、冲突检测 |
| 知识层 | **M3 世界模型** | 原子/离子/分子/晶体/溶液/电极模型与能量阶梯、水合作用 |
| 知识层 | **M4 机理引擎** | 氧化还原与溶解/溶液平衡的机制级解析 |
| 推理层 | **M5 题目结构化解析** | 自然语言题目 → 条件/现象/设问的结构化表示 |
| 推理层 | **M6 推理引擎** | 正推、反推、多解判定、推理链 DAG |
| 推理层 | **M7 试剂与顺序规划** | 干扰分析、序列规划、反事实检查 |
| 支撑 | **M8 题库与数据管线** | 采集、清洗、标注、入库、版本 |
| 支撑 | **M9 校验与回归评测** | 结构/守恒/一致性校验，回归与缺口报表 |
| 交互层 | **M10 引导交互** | 引导状态机、分级提示、错因诊断 |
| 交互层 | **M11 可解释输出与可视化** | 推理 DAG 渲染、能量阶梯/水合/流程图 |
| 交互层 | **M12 应用与接口层** | 会话接入、题目输入/进度/复盘 API 与会话组装 |

模块与规划六大方面的对应关系：

| 规划方面 | 主责模块 | 协作模块 |
| --- | --- | --- |
| 知识范围 | M1 | M2、M8 |
| 规则优先顺序 | M2 | M1、M4、M9 |
| 深层虚拟环境 | M3 | M4、M11 |
| 内部机理 | M4 | M2、M3、M6 |
| 推理能力 | M6、M7 | M2、M5、M11 |
| 题库 | M8 | M1、M2、M9 |

关键约束：
- **M6 不直接读题目原文**，只吃 M5 的结构化结果；**M6 不直接说人话**，只输出结构化结论与依据链，由 M10/M11 表达。
- **M2 是唯一裁决者**：M4/M6/M7 不得自行绕过仲裁直接下结论。
- **M8 入库前必须过 M9**：未通过校验的题目不得进入正式题库。

## 3. 模块明细

> 契约口径：`已实现` 的签名以 `src/` 下真实代码为准；标 `未实现` 的仅为规划契约，落地时按 C# 命名风格实现。

### M0 工程骨架与规范

| 项 | 内容 |
| --- | --- |
| 职责 | 仓库目录结构、编码规范、配置管理、文档规范、依赖管理与本地开发脚本；不含业务逻辑 |
| 输入 | D1 已定（C# / .NET 8）、文档与编码约定 |
| 输出 | `CogniThink.Chem.sln`（`Core` / `Cli` / `Tests`）、`Directory.Build.props`、`.editorconfig`、`.gitignore`、决策记录模板 |
| 依赖 | 无 |
| 不负责 | 业务规则、题库内容、界面设计 |
| 验收要点 | `dotnet build` 零警告零错误；`dotnet test` 可跑通冒烟用例；新成员按文档可在本地拉起工程 |

### M1 知识本体与覆盖清单

| 项 | 内容 |
| --- | --- |
| 职责 | 维护高中化学知识点条目（`knowledge_id`）、层级（主干/延伸）、前置与关联关系、教材出处；提供按模块/关键词/关联规则检索 |
| 输入 | 教材与课标、覆盖清单（规划第 2 节） |
| 输出 | 知识条目集合、覆盖矩阵、缺口清单（无规则/无题目的主干点） |
| 依赖 | M0 |
| 不负责 | 规则内容、题目内容 |
| 接口契约 | 已实现：`TryGet(id, out KnowledgeItem)` / `GetRequired(id)`、`Search(string? keyword, KnowledgeModule? module)`、`DirectPrerequisites(id)` / `PrerequisiteChain(id)`、`ModuleCoverage()`、`Validate() → ValidationReport`（名称、教材出处、前置引用一致性校验）；未实现：`CoverageReport()`（"主干无规则/无用例"缺口报表，T1-9） |
| 验收要点 | 主干知识点 100% 有条目且带教材出处；任一条目可反查规则与题目 |
| 决策关联 | D3（建议：人教版 2019）：`textbookRef` 必填；若切换版本，只需补"版本差异表"并调整该字段，不改结构 |

### M2 规则库与仲裁

| 项 | 内容 |
| --- | --- |
| 职责 | 规则声明式存储与加载；分层（L0–L4）；优先级裁决（硬约束过滤 → 条件匹配 → 特异性 → 证据强度 → 学段 → 教材一致性）；冲突检测与冲突组管理；例外覆盖 |
| 输入 | 规则条目（含元数据与用例）、当前条件集、候选结论集 |
| 输出 | 裁决结果（选中/淘汰及理由）、冲突报告、覆盖关系说明 |
| 依赖 | M1 |
| 不负责 | 题目解析、话术生成、机理数值计算（交给 M4） |
| 接口契约 | 已实现：`RuleEngine.Decide(FactContext context, IEnumerable<string>? ruleIds = null) → Verdict { Kind, Selected, Candidates, Rejected[{Rule, Stage, Reason}], AppliedConstraints, Trace, Note }`；`RuleEngine.Activate(FactContext, IEnumerable<Rule>? scope = null)`；`FactContext`（键值事实集合，规则前提的求值上下文）；`ConflictScanner.Scan(IEnumerable<Rule>)`；`RuleSetValidator.Validate(IEnumerable<Rule>, KnowledgeBase)`；`IConservationValidator`（L0 硬约束入口，当前仅 `PassThroughConservationValidator` 空实现，待 T2-6） |
| 验收要点 | 同一输入可复现同一裁决；冲突对可被自动发现；每条规则均有回归用例（显式或用自动激活用例）；裁决日志可完整解释"为什么选它" |
| 决策关联 | D3：主干/延伸口径由 `GradeScope` 承载，切换教材版本不改变仲裁算法 |

### M3 世界模型

| 项 | 内容 |
| --- | --- |
| 职责 | 提供微粒与能量层面的可推演模型：电子层/能级填充、逐级电离能、晶格能与水合能、离子-偶极与氢键、介电屏蔽；输出趋势判断与机制解释（含 `evidence_level`） |
| 输入 | 元素/物质标识、条件（温度、介质、浓度定性） |
| 输出 | 趋势结论（谁强谁弱、方向）、解释链节点、边界声明（热力学/动力学区分、只给趋势） |
| 依赖 | M0、M1 |
| 不负责 | 给出精确数值、替代查表、直接判定题目结论 |
| 接口契约 | 未实现（T2-2、T2-3）：`ElectronShell(element)`、`IonizationTrend(a, b)`、`HydrationCompare(ionA, ionB)`、`Explain(mechanismId) → nodes[]` |
| 验收要点 | 至少 3 条示范解释链可复现且标注层级；任何解释不得与教材主干结论矛盾；不输出无来源绝对值 |

### M4 机理引擎

| 项 | 内容 |
| --- | --- |
| 职责 | 氧化还原：价态图谱、电子转移计数、半反应配平（酸碱介质）、强弱比较、电池/电解电极过程、介质与浓稀效应；溶解与溶液平衡：Ksp/Q 判据、同离子、沉淀转化与分步沉淀、电离、水解、三大守恒、耦合平衡、近似假设输出 |
| 输入 | 结构化反应/体系描述（来自 M5）、世界模型趋势（M3）、规则（M2） |
| 输出 | 机制级解析：半反应、配平结果、平衡常数表达式、方向判定、近似假设清单、陷阱提示 |
| 依赖 | M2、M3 |
| 不负责 | 题目解读、引导话术 |
| 接口契约 | 未实现（T2-6～T2-11）。当前仅有化学式/方程式基础：`Species.Parse(string)`、`ChemicalEquation.Parse(string)`、`ChemicalEquation.ValidateBalance() → ValidationReport` |
| 验收要点 | 配平结果原子/电荷双守恒；沉淀转化与水解方向判定与教材一致；近似假设必被列出 |

### M5 题目结构化解析

| 项 | 内容 |
| --- | --- |
| 职责 | 把题干拆为条件（物质/浓度/温度/介质/操作）、现象、设问（多小问拆开）；识别信息缺失并生成追问；给出置信度与不确定处标记。解析器统一为 `IQuestionParser` 抽象，LLM 实现与规则实现可互换（D2 建议） |
| 输入 | 题目原文（文本；是否支持图片见 D5） |
| 输出 | 结构化题目对象（符合题库 schema 的条件/现象/设问部分）+ 缺失信息清单 |
| 依赖 | M1、M2（作为解析目标词表） |
| 不负责 | 求解、判定结论；也不允许由 LLM 直接给出化学结论 |
| 接口契约 | 未实现（T3-2）：`IQuestionParser.Parse(string stem) → ParsedQuestion { Conditions[], Phenomena[], Asks[], Missing[], Confidence }`；`ILlmClient` 与 LLM 适配器同样未实现（D2 待确认） |
| 验收要点 | 骨干题型（无机推断、实验探究、原理计算）解析字段完整率达标；缺失信息必须显式列出而非猜测补全；无 LLM 时能退化为规则解析 |
| 决策关联 | D2：接口先定，LLM 适配器可后置；降级路径必须存在 |

### M6 推理引擎

| 项 | 内容 |
| --- | --- |
| 职责 | 正向推理（候选反应 → 守恒校验 → 仲裁 → 现象/产物）；反向推理（候选生成 → 约束过滤 → 多解保留）；结论三态（确定/候选集/信息不足）；推理链 DAG 构建 |
| 输入 | M5 结构化题目、M2 规则、M3/M4 机制解析 |
| 输出 | 结论 + 推理 DAG（节点含 `rule_id`/`knowledge_id`/`evidence_level`）+ 淘汰候选及理由 + 判别需求 |
| 依赖 | M2、M3、M4、M5 |
| 不负责 | 生成自然语言解释、决定提示层级 |
| 接口契约 | 未实现（T3-4、T3-5、T3-10）：`SolveForward(ctx)`、`SolveBackward(observations, constraints)`、`ExplainChain(goal) → dag` |
| 验收要点 | 每步有依据、无跳步；多解必须保留候选集；无规则可解时返回"超出覆盖"而非编造 |

### M7 试剂与顺序规划

| 项 | 内容 |
| --- | --- |
| 职责 | 干扰分析（共存物对检验的干扰）、掩蔽/分离方案、加入顺序的拓扑约束、过量控制、判别实验选择（信息增益最大）、反事实检查 |
| 输入 | 目标（检验/除去/制备/鉴别）、体系组成、M6 的候选集 |
| 输出 | 操作序列（每步：试剂、目的、现象、约束）、顺序颠倒的后果、判别实验建议 |
| 依赖 | M2、M6 |
| 不负责 | 实验安全之外的工艺设计、仪器选型 |
| 接口契约 | 未实现（T3-7～T3-9）：`PlanReagents(goal, system) → steps[]`、`Discriminate(candidates) → test`、`Counterfactual(plan, swap)` |
| 验收要点 | 典型鉴别/除杂场景方案与教材一致；顺序错误能被显式指出后果 |

### M8 题库与数据管线

| 项 | 内容 |
| --- | --- |
| 职责 | 来源登记（含 license）、采集与清洗、去重（题干指纹）、多小问拆分、推理链标注、入库与版本管理、统计报表 |
| 输入 | 原始题目（教材/真题/公开数据集/自建）、覆盖清单（M1） |
| 输出 | 合规题库（含标注）、版本快照、覆盖与缺口报表 |
| 依赖 | M1、M2、M6（用于跑通验证） |
| 不负责 | 规则裁决、教学话术 |
| 接口契约 | 未实现（T4-3～T4-7）。已实现的数据加载：`ChemDataLoader.LoadAll(string? dataRoot = null)`、`ChemDataLoader.LoadKnowledge/LoadRules/LoadRuleTests`、`DataRoot.Resolve(string?)`；`Ingest` / `Publish` / `Coverage` 均未实现 |
| 验收要点 | 每题有来源与 license；主干知识点均有题；版本可回滚 |
| 决策关联 | D4（建议）：仅自建题入库，`source.origin=self`、`license=internal`；外部来源缺 license 时校验器报错，不得发布 |

### M9 校验与回归评测

| 项 | 内容 |
| --- | --- |
| 职责 | 五道质量关（结构、化学正确性、答案一致性、多解检测、人工复核记录）；规则回归；题库端到端通过率；冲突与缺口报表 |
| 输入 | 题库、规则库、求解输出 |
| 输出 | 校验报告、回归报告、缺口清单、发布准入结论 |
| 依赖 | M1、M2、M6、M8 |
| 不负责 | 修复内容（只报告，修复由对应模块负责） |
| 接口契约 | 部分实现：`RuleRegressionRunner.Run(IEnumerable<RuleTestCase> cases, bool includeAutoActivation = true) → RuleRegressionReport`（仅规则级，无版本对比）、`ValidationReport`（校验结果载体）；未实现：`CheckQuestion(question)`（T4-4、T4-5）、带版本绑定的题库端到端 `Regress(ruleSet, bankVersion)`（T4-9） |
| 验收要点 | 回归结果带版本号可对比；不通过项必须定位到题或规则；冲突数为发布硬门槛 |

### M10 引导交互

| 项 | 内容 |
| --- | --- |
| 职责 | 引导状态机（理解题目 → 定位卡点 → 分层提示 L1–L4 → 确认理解 → 迁移练习）；错因诊断（概念/条件/顺序/计算/读题）；提示话术组装；不越权给答案 |
| 输入 | M6 推理 DAG 与结论三态、M7 方案、学生作答与反馈 |
| 输出 | 提示文本、追问、诊断结论、下一步建议 |
| 依赖 | M6、M11 |
| 不负责 | 化学判定（只消费结论） |
| 接口契约 | 未实现（T5-1～T5-3）：`Hint(state, level)`、`Diagnose(studentStep)`、`NextAction(state)` |
| 验收要点 | 默认不输出 L4；每级提示不泄露下一级内容；诊断可回溯到具体卡点 |
| 决策关联 | D5（建议）：以"分步卡片"承载 L1–L4，每张卡片只含一级提示；对话只作辅助入口 |

### M11 可解释输出与可视化

| 项 | 内容 |
| --- | --- |
| 职责 | 推理 DAG 的可读呈现；能量阶梯图、离子水合示意、实验流程图、滴定/分布曲线（概念级）等图元的生成；解释分层标注（考试依据 vs 帮助理解） |
| 输入 | M6 DAG、M3/M4 解释节点 |
| 输出 | 结构化视图模型（供前端渲染），不直接产出像素 |
| 依赖 | M3、M4、M6 |
| 不负责 | 判定结论、决定提示层级 |
| 接口契约 | 未实现（T5-4、T5-5）：`RenderModel(dag)`、`ExplainView(mechanismId)` |
| 验收要点 | 每个图元可回溯到节点；微观示意与判定依据在视觉上可区分 |
| 决策关联 | D5（建议）：输出与框架无关的视图模型（步骤卡、DAG、能量阶梯、水合示意），Web 优先、移动自适应 |

### M12 应用与接口层

| 项 | 内容 |
| --- | --- |
| 职责 | 会话管理、题目输入与解析进度、求解/提示/复盘接口、权限与配额、日志与埋点（是否收集学情数据见 D6） |
| 输入 | 前端请求、M10/M11 输出 |
| 输出 | API 响应、会话记录、使用指标 |
| 依赖 | M5、M10、M11 |
| 不负责 | 业务规则与教学内容 |
| 接口契约 | 未实现（T5-6）：`CreateSession()`、`SubmitQuestion(text)`、`RequestHint(level)`、`GetReview(questionId)`（进程内服务 + 可选 HTTP 适配，D5 未锁定前端框架） |
| 验收要点 | 接口契约稳定、错误可读；不泄露内部规则细节（除非复盘模式） |
| 决策关联 | D5：先做进程内服务层，HTTP 适配与前端在形态确认后接入；D6：默认不落盘个人数据 |

## 4. 跨模块数据契约（统一 ID 与节点结构）

| 契约 | 内容 | 约束 |
| --- | --- | --- |
| `knowledge_id` | 知识点唯一 id | 必须存在于 M1；规则与题目只能引用已存在的 id |
| `rule_id` | 规则唯一 id（域前缀） | 必须属于唯一 `conflict_group` |
| `question_id` | 题目唯一 id | 多小问拆分为 `question_id.sub` |
| 推理节点 | `{step, premises[], rule_id, conclusion, evidence_level, confidence}` | `evidence_level ∈ {教材结论, 规律推演, 微观机制示意}` |
| 结论三态 | `确定 / 候选集 / 信息不足` | 候选集必须附判别实验 |
| 近似假设 | `{assumption, impact, source}` | 计算类结论必须携带，不得默认省略 |

### 4.1 实现约定（D1 已定）

| 项 | 约定 |
| --- | --- |
| 序列化 | JSON（`System.Text.Json`）；字段 camelCase；枚举用字符串；外层 `{ "version": "0.1", "items": [...] }`；允许注释与尾逗号 |
| 类型映射 | 数据文件 → 强类型对象（如 `Rule`、`KnowledgeItem`）；不使用 `dynamic`，避免"讲得通就过" |
| 校验入口 | 已实现：`KnowledgeBase.Validate()`、`RuleSetValidator.Validate(rules, knowledge)`、`ChemicalEquation.ValidateBalance()`；未实现：题库 `Validate(question)`（T4-4） |
| 命名空间 | 已实现：`CogniThink.Chem.Core`（`ModuleInfo`）、`.Chemistry`（`Species`、`ChemicalEquation`）、`.Data`（`ChemDataLoader`、`DataRoot`）、`.Diagnostics`（`ValidationReport`）、`.Evaluation`（`RuleTestCase`、`RuleRegressionRunner`）、`.Knowledge`（`KnowledgeBase`、`KnowledgeItem`、`KnowledgeModule`、`KnowledgeTier`）、`.Rules`（`Rule`、`RuleEngine`、`FactContext`、`ConflictScanner`、`RuleSetValidator`、`Verdict`）；未实现（T2 起）：`World`、`Mechanisms`、`Reasoning`、`Bank`、`Tutoring`、`Explain` |
| 错误处理 | 数据错误抛异常或记入 `ValidationReport`；不允许静默跳过（尤其冲突与守恒失败） |
