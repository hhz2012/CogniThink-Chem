## 1. 目标与定位

### 1.1 一句话定位

面向高中生的化学**思维陪伴**工具：不直接交付答案，而是把"该往哪想、为什么这样想、依据是什么"逐层展开，并保证每一条推理都能被回溯检查。

### 1.2 三条产品原则

| 原则 | 含义 | 反例（明确不做） |
| --- | --- | --- |
| 引导优先 | 默认只给方向性提示，逐步加深，学生自己走完关键步骤 | 输入题目直接输出完整答案 |
| 过程可检查 | 每个结论都挂接规则来源与适用条件，可被质疑、可被推翻 | 只给结论，或给"看起来对"的解释 |
| 微观可解释 | 宏观规律能向下追到微粒、能量与作用力层面的机制 | 用"记住就行"搪塞，或编造机理 |

### 1.3 目标

- **覆盖**：高中化学必考主干知识成体系覆盖（见第 2 节），并对延伸内容做"可解释但不作判定依据"的分层处理。
- **推理**：既能由条件正推现象/产物，也能由实验现象反推物质组成与结构；能对试剂选择与加入顺序给出可检查的方案。
- **解释**：对氧化还原、溶解与溶液平衡等核心机理给出"宏观规律 ↔ 微观模型"双向打通的解释。
- **引导**：在 L1–L2 级提示内让学生独立解决大部分题目，而不是靠给答案提效。

### 1.4 非目标（本期不做）

- 不做拍照搜题式答案库；不以"秒出答案"作为卖点。
- 不做竞赛/大学内容作为解题依据（可作延伸解释，必须显式标注）。
- 不做无人工审核的自动生成题直接入库。
- 不做精确量子化学或分子动力学计算；虚拟环境定位为"教学解释级半定量模型"。

### 1.5 成功判据（初版，待试点数据校准）

| 维度 | 指标 | 说明 |
| --- | --- | --- |
| 知识覆盖 | 主干知识条目覆盖率 | 对照覆盖清单逐条打勾 |
| 规则质量 | 回归题库通过率、规则冲突数 | 冲突必须为 0 才能发布 |
| 推理质量 | 推理链可追溯率（每步有规则+条件） | 目标 100%，且无"跳步" |
| 引导效果 | L1/L2 提示内解决率 | 需真实学生试点数据，见 D9 |
| 题库质量 | 双人复核通过率、多解题标注率 | 多解必须显式标出，不许强行唯一 |

## 3. 规则优先顺序：判定、冲突与例外

多条知识同时可用是化学推理的常态（例如"强酸制弱酸"与"难溶物生成"同时成立）。必须有一套**确定性、可解释、可测试**的仲裁机制，而不是让模型自由选择。

### 3.1 规则分层

| 层 | 名称 | 内容示例 | 性质 |
| --- | --- | --- | --- |
| L0 | 守恒与定义 | 原子/电荷/电子/物料/质子守恒，化合价定义，物质的量关系 | **硬约束**，违反即淘汰，不参与"优先级比较" |
| L1 | 原理与定律 | 勒夏特列原理、平衡常数、Ksp 判据、盖斯定律、电极电势方向 | 强，需条件匹配 |
| L2 | 结构性规律 | 周期律、金属活动性顺序、越弱越水解、相似相溶、强酸制弱酸 | 中，常有例外 |
| L3 | 条件性经验 | 浓/稀差异（HNO₃、H₂SO₄）、温度与催化剂特定效应、介质酸碱性影响 | 强，但仅在该条件出现时可用 |
| L4 | 特例与例外 | AlCl₃ 为共价化合物、HF 为弱酸、AgCl 溶于氨水、SiO₂ 与 HF 反应 | **覆盖**同层一般规则，但必须有明确触发条件 |

> 层级不是简单的"数字小优先"。正确顺序是：**先硬约束淘汰 → 再看条件是否成立 → 再看特异性（例外覆盖一般）→ 再看证据强度**。

### 3.2 仲裁判定顺序（逐步执行，任一步可终止）

1. **硬约束过滤（L0）**：候选结论若违反守恒或定义（如电子转移数不守恒、电荷不守恒、化合价越界），直接淘汰，不进入打分。
2. **条件匹配（适用性）**：规则前提"全部满足"优先于"部分满足"；依赖默认假设（如"稀溶液""常温"）的规则降权，并在解释中显式写出假设。
3. **特异性优先**：L4 例外规则在其触发条件成立时，覆盖 L1–L3 的一般结论；L3 条件性规则覆盖 L2 规律。覆盖必须写明"因为满足了哪个例外条件"。
4. **证据强度**：定量计算/实测现象 > 定性规律 > 记忆型结论；定性结论不得压过定量结论。
5. **学段合规**：主干（教材必考）优先于延伸；延伸只能用于解释，不能单独定结论。
6. **教材一致性**：与教材表述冲突的规则一律降为"待评审"，不参与裁决。
7. **未能消解** → 不强行选一个：输出**并列候选 + 判别方法**（见 3.4）。

### 3.3 冲突类型与处理策略

| 冲突类型 | 典型场景 | 处理 |
| --- | --- | --- |
| 硬矛盾 | 同一命题被推出正反两结论 | 立即中止该分支，记录冲突对，触发规则评审；**禁止跳过** |
| 条件互斥 | 两规则前提不可能同时成立 | 按题目实际条件选择，另一条不激活 |
| 特例覆盖 | AlCl₃ 熔点低 vs "离子化合物熔沸点高" | 特例生效，解释中标注"例外及其原因" |
| 强度冲突 | 定性规律 vs 平衡计算 | 以定量为准，定性作为趋势说明 |
| 数值异常 | 计算结果超数量级、与守恒不符 | 标为"可疑"，回退一步检查，不对外输出结论 |
| 多解冲突 | 现象不足以区分多种物质 | 保留候选集，给出判别实验，**不猜唯一答案** |

### 3.4 多解与不确定性

现象不充分是化学题的固有特征（例如"白色沉淀"可对应多种物质）。设计上必须把"不确定"当作一等公民：

- 结论有三种状态：`确定` / `候选集（含置信排序）` / `信息不足`。
- 候选集必须附**判别实验建议**：选择能把候选集"劈开"的试剂或操作，并说明预期现象差异。
- 交互层据此提问，而不是直接给"标准答案"。

### 3.5 规则库的组织与维护

**每条规则的元数据（草案，schema 在任务 T1-3 定稿）**

| 字段 | 说明 |
| --- | --- |
| `rule_id` | 唯一标识，按域前缀（如 `RED-`, `SOL-`, `EQ-`, `STR-`） |
| `layer` | L0–L4 |
| `knowledge_id` | 归属知识点，必须存在于覆盖清单 |
| `preconditions` | 结构化前提（物质类别、条件、现象、浓度/介质等） |
| `conclusion` | 结构化结论（不是自然语言句子） |
| `exceptions` | 关联例外规则 id 列表 |
| `grade_scope` | 必修 / 选择性必修 / 延伸 |
| `evidence_type` | 守恒 / 定量 / 定性 / 记忆 |
| `source` | 教材章节或课标条目（可追溯） |
| `conflict_group` | 互斥结论分组，用于自动冲突扫描 |
| `tests` | 回归用例 id 列表，**无用例不得入库** |

**维护流程**

1. 提案：新增/修改规则必须说明动机（错题、缺口、教材变动）。
2. 冲突扫描：与 `conflict_group` 内规则做结论矛盾检测，与例外规则做覆盖一致性检测。
3. 回归：跑该规则关联用例 + 全量回归子集，不允许通过率下降。
4. 发布：规则库带版本号，与题库版本绑定；变更留 changelog。
5. 定期体检：主干知识点"无规则/无题目"清单、长期未命中的规则、频繁冲突的规则组。

### 3.6 为什么不用"让模型自己判断"

LLM 在多规则竞争时倾向于"讲得通就选"，且会编造依据。因此：**裁决必须在确定性规则引擎内完成**，LLM 只负责把题目语言解析成结构化条件、把结构化结论表述成自然语言（见第 6 节技术选择）。

## 4. 深层虚拟环境：可推演的化学世界模型

这一层是"可解释"的底座。它不追求数值精度，追求**机制方向正确、层次清楚、边界诚实**。

### 4.1 模型实体与属性

| 实体 | 关键属性 | 支撑的上层结论 |
| --- | --- | --- |
| 原子/离子 | 核电荷、电子排布、有效核电荷（定性）、半径、逐级电离能、电子亲和能 | 金属性/非金属性递变、还原性/氧化性强弱 |
| 分子 | 键类型与键能（定性）、极性、空间构型、氢键位点 | 熔沸点、溶解性、极性判断 |
| 晶体 | 晶格类型、晶格能、配位数 | 熔点、硬度、溶解性 |
| 溶液 | 溶剂、离子强度（定性）、pH、饱和度 | 电离、水解、沉淀溶解 |
| 电极 | 电极材料、标准电极电势（相对值）、介质 | 原电池/电解池电极反应与放电顺序 |

### 4.2 电子层与能量阶梯

**能解释什么**

- 电子按能层/能级填充（构造原理、洪特、泡利）→ 为什么某元素价电子构型如此 → 为什么族性质相似。
- 逐级电离能跳跃 → 为什么某价态稳定（如 Na⁺、Mg²⁺ 的常见价态）。
- 电离能低 + 水合能高 → 为什么该金属还原性强/电极电势低。

**解释链示例（金属还原性递变）**

```
Na 第一电离能 < Mg 第一电离能
        +
Na⁺ 电荷密度低、水合能绝对值大（相对 Mg²⁺ 的电荷补偿）
        ↓
标准电极电势 E°(Na⁺/Na) 更负
        ↓
水溶液中 Na 的还原性强于 Mg（热力学层面）
```

**必须标注的边界**

- 该模型只能给出**趋势与相对大小**，不给绝对值；不替代查表（电极电势表、电离能表）。
- **热力学 ≠ 动力学**：Li 与水反应比 Na 缓和，但 E° 更负；解释时必须区分"能否反应"与"反应快慢"（后者涉及熔点、水合动力学、氧化膜，教材不量化）。
- 解释节点要带 `evidence_level`：`教材结论` / `规律推演` / `微观机制示意`。考试判定只能用前两类。

### 4.3 离子间作用力与水合力

| 作用 | 定性模型 | 用途 |
| --- | --- | --- |
| 离子-离子（库仑） | 与 q₁q₂/r² 同向变化 | 晶格能大小、熔点高低、沉淀倾向 |
| 离子-偶极（水合） | 电荷密度越高、半径越小，水合越强 | 溶解性、水合热、离子迁移 |
| 氢键 | 供体/受体匹配、方向性 | 沸点异常（H₂O、HF、NH₃）、溶解度 |
| 介电屏蔽 | 水的介电常数大 → 削弱离子间吸引 | 电解质在水中易解离；加有机溶剂促沉淀 |

**解释链示例**

- **AgCl 溶于氨水**：`Ksp(AgCl)` 与 `[Ag(NH₃)₂]⁺` 的配位平衡耦合，总反应平衡常数 = Ksp × β₂，故可行。这是"沉淀-配位耦合"，不是"AgCl 变了性质"。
- **Na₂CO₃ 溶液显碱性**：CO₃²⁻ 水解，`Kh = Kw/Ka₂( H₂CO₃)`，故 Kh 较大 → 碱性强于 NaHCO₃。
- **CaCO₃ 难溶而 Ca(HCO₃)₂ 可溶**：晶格能与水合能的相对大小差异 + 离子电荷数差异。

### 4.4 与上层的关系（解释分层）

```
微观机制（能级/水合/配位）  ← 帮助理解，不作判定依据
        ↓
原理与规律（L1/L2 规则）    ← 判定依据
        ↓
题目结论（现象/产物/顺序）  ← 可检查的输出
```

**设计要求**：任一结论在输出解释时，必须能标出它属于哪一层；不允许把"微观示意"当作"考试依据"混在推理链里。

## 5. 内部机理的深层解析

### 5.1 氧化还原机理

| 主题 | 需要具备的解析能力 | 常见陷阱（必须有规则覆盖） |
| --- | --- | --- |
| 价态与电子转移 | 常见元素价态图谱、电子转移数与方向、氧化剂/还原剂判定 | 同一物质既是氧化剂又是还原剂（歧化）、归中反应 |
| 方程式配平 | 半反应法：配平原子 → 配平电荷（H⁺/OH⁻/H₂O 补全）→ 合并 | 酸性/碱性介质混用、H₂O 漏配 |
| 强弱比较 | 电极电势、活动性顺序、反应方向（强氧化剂+强还原剂→弱…） | 浓度/酸碱性改变氧化性（稀硝酸、MnO₄⁻ 在酸/碱中） |
| 原电池 | 电极判断、电子流向、离子迁移、盐桥/膜、正负极反应 | 燃料电池介质（酸/碱/熔融碳酸盐）写法不同 |
| 电解池 | 阳极/阴极、放电顺序、电解产物、电量-物质的量换算 | 惰性/活性电极区别、电镀与精炼的阳极差异 |
| 介质影响 | 钝化（浓 H₂SO₄/浓 HNO₃ 与 Fe、Al）、浓稀差异 | 把"常温钝化"当成"不反应" |

**示例（歧化与归中的方向判断）**：Cl₂ + NaOH → Cl⁻ + ClO⁻（歧化，同一元素升降价）；ClO₃⁻ + Cl⁻ + H⁺ → Cl₂（归中，价态向中间靠拢）。判据是"价态变化是否向中间靠拢"，不是死记方程式。

### 5.2 溶解与溶液平衡机理

| 主题 | 解析能力 | 关键关系 |
| --- | --- | --- |
| 溶解平衡 | 饱和状态、溶解/结晶速率相等、Q 与 Ksp 比较判方向 | Q>Ksp 析出；Q<Ksp 可继续溶解 |
| 同离子效应 | 加入共同离子使溶解度下降 | 定量估算（近似） |
| 沉淀转化 | 由 Ksp 求转化反应平衡常数，判断方向 | K = Ksp(难溶)/Ksp(更难溶) 的数量级比较 |
| 分步沉淀 | 按 Ksp 与离子浓度计算开始沉淀/沉淀完全的先后 | 需离子浓度而非只看 Ksp |
| 弱电解质电离 | Ka/Kb、电离度、稀释定律 | α ≈ √(Ka/c)（近似条件需标注） |
| 盐类水解 | Kh = Kw/Ka（或 Kw/Kb）、越弱越水解、影响因素 | 温度促进、稀释促进、加酸/碱抑制 |
| 三大守恒 | 电荷守恒、物料守恒、质子守恒 | 用于离子浓度大小比较 |
| 耦合体系 | 沉淀+配位、沉淀+酸碱、水解+电离 | 联立平衡，输出近似假设 |
| 图像 | 滴定曲线、分布系数、Ksp 对数图 | 定性读图为主，定量需标注近似 |

**示例（沉淀转化方向）**：AgCl(s) + I⁻ ⇌ AgI(s) + Cl⁻，K = Ksp(AgCl)/Ksp(AgI) ≫ 1，故向生成 AgI 方向进行。判断依据是平衡常数，不是"碘化银更难溶"这句话本身。

**计算边界**：忽略活度系数、忽略体积变化（除非题目给出）、近似条件（如 c/Ka > 500）必须显式输出，不能默默省略。

## 6. 推理能力

### 6.1 正向推理（条件 → 现象/产物）

- 输入：结构化条件（物质、浓度、温度、介质、操作顺序）。
- 过程：候选反应生成 → L0 守恒校验 → 规则仲裁 → 现象/产物预测。
- 输出：结论 + 依据链 + 被淘汰的候选及淘汰理由（可检查性来源）。

### 6.2 反向推理（现象 → 组成/结构）

这是本项目的核心差异点。流程：

1. **候选生成**：按现象特征（颜色、状态、气味、溶解性、焰色、特征反应）检索知识库，得到候选物质集合。
2. **约束传播**：用题目其余条件（共存、反应关系、定量比例）逐条过滤。
3. **区分性检验设计**：若候选 >1，挑选"能把候选集最大程度劈开"的试剂/操作（信息增益最大），并给出各自的预期现象差异。
4. **结论分级**：唯一 → `确定`；多个但可判别 → `候选集 + 判别方案`；条件不足 → `信息不足`，并指出缺哪个关键信息。

**要求**：绝不"选一个最像的"当答案；多解必须保留。

### 6.3 试剂选择与加入顺序

| 子能力 | 说明 |
| --- | --- |
| 干扰分析 | 检验 A 时，哪些共存离子/基团会产生相同或相似现象 |
| 掩蔽与分离 | 用配位、沉淀、pH 调节消除干扰 |
| 顺序约束 | 必须先除干扰再加检验试剂（如检验 SO₄²⁻ 先盐酸酸化排除 CO₃²⁻/SO₃²⁻） |
| 过量控制 | 判断"过量/适量/少量"对后续步骤的影响 |
| 反事实检查 | 输出"若把顺序颠倒会发生什么"，用于自检与教学 |

输出形态：`操作序列 + 每步目的 + 每步现象 + 顺序错误的后果`。

### 6.4 引导策略（交互层的推理接口）

| 级别 | 内容 | 何时使用 |
| --- | --- | --- |
| L1 | 方向提示（"先判断这是什么类型的反应"） | 默认起点 |
| L2 | 知识点提示（点出适用规律，不给结果） | L1 后仍卡住 |
| L3 | 下一步操作提示（具体到"该比较哪个量"） | 仍卡住 |
| L4 | 完整推理（含答案） | 仅学生主动请求，且用于复盘 |

配套：**错因诊断**（概念混淆 / 忽略条件 / 顺序错误 / 计算失误 / 读题遗漏），诊断结果决定 L2 提示指向哪个知识点。

## 7. 题库规划

### 7.1 来源与范围

| 来源 | 优点 | 风险 | 处理 |
| --- | --- | --- | --- |
| 教材例题与习题 | 与规则天然对齐、权威 | 数量少 | 仅内部评测；入库需授权（D4） |
| 高考真题、省市模拟 | 贴近考纲、题型全 | **版权与授权** | 先做授权核查（D4），未授权仅内部评测用 |
| 公开数据集/开源题库 | 起量快 | 质量参差、结构不一 | 清洗 + 双人复核后才入库 |
| 自建（教师命题 / 规则生成后人工审） | 可控、可针对缺口 | 成本高、易有错 | 建立命题与审核规范，生成题必须人工签核 |

**建议（D4，待确认）**：题库以自建题起步（`origin=self`、`license=internal`）；教材例题、高考真题、省市模拟、公开数据集一律先登记 license、仅作内部评测，授权边界确认前不对外发布。各类来源的风险与需确认范围见 [decisions.md](./decisions.md) D4 一节；本规划不代替用户做授权结论。

**范围**：五大模块 × 题型（选择、填空、实验探究、工艺流程、有机推断、原理计算）；难度分基础/中档/压轴；每题标注 `knowledge_id` 列表。

### 7.2 数据结构（草案，由 T4-1 定稿）

```
question
├── question_id
├── source { origin, year, region, license, url }
├── stem                      # 题干原文
├── conditions[]              # 结构化条件：物质/浓度/温度/介质/操作
├── phenomena[]               # 现象（可含多义，用于反向推理）
├── sub_questions[]           # 多小问必须拆开
│   ├── ask
│   ├── answer
│   └── reasoning_chain[] { step, premise_ids, rule_ids, conclusion }
├── knowledge_ids[]
├── difficulty
├── discriminative_tests[]    # 用于区分候选的试剂/操作
└── validation { schema_ok, balance_ok, answer_unique, reviewed_by[] }
```

### 7.3 质量校验（五道关）

1. **结构校验**：schema、必填字段、多小问拆分是否彻底。
2. **化学正确性**：方程式原子/电荷守恒自动校验；化学式合法性校验。
3. **答案一致性**：用规则引擎跑推理链，结论必须与标准答案一致；不一致的题要么改题、要么改规则，不允许"跳过"。
4. **多解检测**：反向推理题必须检查是否存在其他合理解，存在则标注候选集而非单答案。
5. **人工复核**：双人独立复核 + 抽样复审；记录复核人与版本。

### 7.4 题库运营

- 版本化：题库版本与规则库版本绑定，回归结果带版本号。
- 统计报表：知识点覆盖矩阵、题型分布、难度分布、多解题比例、规则未覆盖的题（缺口清单）。
- 缺口驱动：优先补充"主干知识点无题"和"有题但规则跑不通"的部分。

## 8. 总体架构

### 8.1 三层分工

| 层 | 职责 | 不负责 |
| --- | --- | --- |
| **知识层** | 覆盖清单、规则库、机理模型、世界模型、题库（确定性知识源） | 不做语言理解、不做对话 |
| **推理层** | 题目结构化、正/反向推理、规则仲裁、守恒校验、冲突检测、推理链输出 | 不生成知识、不决定话术 |
| **交互层** | 引导状态机、分层提示、错因诊断、可解释可视化、会话管理 | 不做化学判定 |

两条支撑：**数据管线**（题库采集/清洗/标注/校验）与**评测回归**（规则回归 + 题库端到端 + 教学试点）。

### 8.2 数据流

```
学生输入题目
   │
   ▼
[交互层] 题目采集 / 意图识别 / 会话状态
   │  原文 + 会话上下文
   ▼
[推理层] ① 结构化解析（条件/现象/设问）
        ② 条件完整性检查 → 缺信息则追问
        ③ 正推 + 反推（规则引擎裁决，L0 守恒校验）
        ④ 冲突检测 / 多解判定
        ⑤ 生成推理 DAG + 分级解释
   │  结构化结论 + 依据链
   ▼
[交互层] 分层提示（L1→L4）/ 错因诊断 / 可视化
   │
   ▼
学生反馈（是否解决 / 卡点）→ 用于引导策略迭代与题库缺口统计
```

### 8.3 关键设计约束

- **LLM 不产出最终化学结论**：只做"自然语言 ↔ 结构化"的双向转换与话术组织；结论由规则引擎给出。
- **每步可回溯**：推理链是 DAG，节点带 `rule_id` / `knowledge_id` / `evidence_level`。
- **不确定显式化**：`确定 / 候选集 / 信息不足` 三态，禁止默默取唯一。
- **单一事实来源**：规则、知识点、题目三者用 id 互相引用，不重复描述。

## 9. 关键技术选择

> D1 已定（C# / .NET 8）；D2–D5 为**建议采纳、待确认**，详见 [decisions.md](./decisions.md)。

| 议题 | 方案 | 理由 | 备选 |
| --- | --- | --- | --- |
| 实现语言与运行时 | **C# / .NET 8**（D1 已定） | 强类型适合规则/命题/依据链建模；`System.Text.Json` 零依赖；`dotnet test` 天然适配规则回归 | Python（生态好但栈割裂）；TypeScript（表达力弱） |
| 架构范式 | 符号规则引擎为主 + LLM 作语言层（神经-符号混合） | 化学结论需要确定性、可解释、可回归；纯 LLM 无法保证一致性与可检查 | 纯 LLM + 校验（风险高）；纯规则（语言理解成本高） |
| LLM 形态 | **云端 API 起步 + `ILlmClient` 抽象**，保留本地/私有化替换点；无 LLM 时退化为规则解析（D2 建议） | 先验证价值，不预付算力成本；抽象后切换只影响一个实现类 | 一开始本地部署（重）；完全不用 LLM（复杂题干解析受限） |
| 规则表示 | 声明式 JSON → C# 强类型对象；枚举以字符串序列化 | 内容可评审、可 diff、可版本化；零依赖加载 | 直接写代码（难评审）；YAML（需引入第三方包，与 D1 约束冲突） |
| 推理实现 | 前向链 + 反向目标驱动（少而准）+ 约束满足（反向推理） | 避免全量规则扫描带来的爆炸 | 纯前向（易爆炸） |
| 解释输出 | 推理 DAG + 模板化自然语言 + `evidence_level` 分层 | 可检查、可审计 | 让 LLM 自由解释（易幻觉） |
| 数据存储 | 起步 JSON 文件（`data/`）+ 内存索引；规模上来再考虑 SQLite | 早期迭代快，避免过度设计 | 一开始上图数据库 |
| 计算 | 内置化学计量、守恒校验与平衡近似计算，输出近似假设 | 高中题需要定量；避免引入超纲 CAS | 外部 CAS（超纲、重） |
| 交互形态 | **分步卡片 + 推理 DAG 视图**，Web 优先、移动自适应；对话仅作辅助入口（D5 建议） | 分级提示本质是步骤流；DAG/能量阶梯需要固定版式 | 纯对话（易越权、难呈现）；画布编辑（成本高） |

## 10. 风险与应对

| 风险 | 等级 | 表现 | 应对 |
| --- | --- | --- | --- |
| 幻觉与错误结论 | 高 | LLM 编造反应或依据 | 结论只由规则引擎产出；L0 守恒强制校验；题库端到端回归 |
| 题库版权 | 高 | 真题/模拟题无法公开使用 | 优先自建与授权；未授权数据仅内部评测；来源字段强制记录 license |
| 规则冲突与例外失控 | 中高 | 同题多结论、例外滥用 | 冲突组自动扫描；例外必须有触发条件与用例；冲突数必须为 0 才发布 |
| 知识覆盖不全 | 中 | 学生问到没覆盖的点 | 覆盖矩阵 + 缺口清单驱动；未覆盖时明确说"超出当前范围"而不是硬编 |
| 过度引导/直接给答案 | 中 | 变成答案机，教学价值下降 | 分级提示 + L4 需主动请求 + 试点评估（D9） |
| 学生用 AI 代做作业 | 中 | 教育合规与口碑风险 | 产品层面强调过程与复盘；不提供一键抄答案路径 |
| 维护成本高 | 中 | 规则/题库随时间腐化 | 元数据 + 用例 + 版本绑定 + 定期体检 |
| 教材版本差异 | 中 | 不同版本表述不同导致判定不一致 | D3 明确基线版本；差异点建"版本差异表" |
